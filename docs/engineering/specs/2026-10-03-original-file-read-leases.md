# 固定四角色原件的内核读租约

承接[研究受控启动与退出协议](2026-10-03-research-controlled-launcher.md)。
原件身份复核能够发现变化，但不能拒绝已打开的写句柄；只声明持有锁或收到
成功状态也不能证明文件仍受保护。本增量在固定执行、签发、控制根和原清单中
全部研究 UID 的既有文件上实际取得 Linux 读租约，并将持有中的句柄接入原
研究捕获流程。状态仍是局部技术验证，完整系统交付继续进行。

## 范围与实际行为

[租约入口](../../../tools/demo_gold_file_leases.py)只接受原已验证公共材料和
VerifiedResearchLayout，沿原固定 ROLE_ROOTS 和完整研究根逐一取实际路径、
UID/GID、文件身份及目录成员。不接受调用者补充路径、替换角色或成功布尔值。
Root 协调进程必须实际为单线程、主线程，持有期间不能转交另一个进程。

沿原 nofollow 打开规则保留每个目录和文件的描述符；普通文件必须单链接、
角色所有、权限受限，秘密名称、别名、重叠根和超出 FD/节点预算均拒绝。只读
打开原文件，不读取其内容，不修改原件或全局内核租约超时。

每个普通文件实际调用 F_SETLEASE/F_RDLCK。已有写句柄、缺少内核能力或
文件系统不支持均失败关闭。Linux 的读租约及超时强制破租行为见
[F_SETLEASE/F_GETLEASE 原始手册](https://man7.org/linux/man-pages/man2/F_GETLEASE.2const.html)。
后续写打开会启动破租流程，因此每次原件复核同时检查待处理 SIGIO 和实际
F_GETLEASE 状态；不能等到超时后仍依据旧报告宣布成功。

目录成员、父路径、实际 inode 和完整元数据仍逐次核对。新文件与同字节换
inode 都使流程拒绝；本机制不会阻止目录重命名、新建文件或未来 Root 操作。
失败和退出都释放全部本次描述符；信号作用域已被其他使用者持有时直接拒绝，
保留原待处理通知。只在本次成功占用通知作用域后回收本次待处理通知。

[原研究协调入口](../../../tools/demo_gold_research_launcher.py)可消费该实际
持有句柄，沿原 roster.capture 生成带额外 live guard 的原 opaque 清单。
原请求、Root peer、原生归档恢复、RECHECK/CLOSE、实际退出及最终报告都复核
同一持有集合。提前关闭或仅提供成功声明不能得到租约验证结果。原不含租约
的技术路径保留，不据此满足完整 writer 验收。

## 已取得的证据与边界

独立自有 Git 对象副本为 b3cf1168 基线加精确四个 Python 文件 overlay。
普通 UID 五组联合 72 PASS/40.21 秒；实际 Root/角色禁网只读容器
8 PASS/101.15 秒。两组各自记录的全部 3008 个 Python 文件前后相同。
原缺模块的红日志、fixture 目录冲突日志、修正后五项及最终八项日志全部保留，
位于 gold-project-closure-20261003-3pr5mrly/root-file-leases。

八项内核检查覆盖完整固定角色/研究 UID 范围、实际已有写句柄拒绝、实际
非阻塞写打开拒绝并使租约失效、新成员和 inode 替换、持有租约时两个实际
研究 UID 的原归档/恢复与受控退出，以及部分获取失败的 FD/信号回收和原有
信号作用域保留。普通测试另外拒绝三种调用者伪造成功状态。

研究输入由原生产者生成，实际 UID、内核租约、setpriv、IPC、原生研究多卷
归档/异路径恢复和真实进程退出确实执行。其他三个角色根在本组是实际属主的
小型夹具文件，未完成这三个角色的原生恢复。systemd manager/cgroup、固定
公共材料和 accepted-release 路径仍是明确夹具边界。容器没有宿主保护状态、
凭据或服务管理器，不将该检查称为现场 sandbox 验收。

成功仅表示 original_file_leases_verified；writer_barrier_verified、
whole_set_verified、submission_enabled 和 economic_authority 仍为 false。
原 cut 在取得文件租约之前已存在，不能据此回溯制造同 cut 停写证明。
