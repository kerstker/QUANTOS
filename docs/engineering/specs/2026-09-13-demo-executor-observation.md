## 行为与接线

`tools.demo_executor_observation` 只在原固定执行 UID 和状态目录下工作。
原私有日志在同一只读事务中检查完整本地链并提取摘要；原文、余额、凭证和成交
载荷不输出给研究端。读预算允许查看已经达到写入上限的日志，写入预算不放宽。
原 `snapshot()` 默认继续检查最近 100 条，不改变既有 Console 合同和历史记录。

汇总保留私有流、BTCUSDC 起点、BTCUSDT 起点、驻留恢复、OMS 和撤单六个环节。
每项保留原记录摘要、观察时间、实际阶段；私有流另保留总记录、业务消息、去重
消息和缺口数。缺失、损坏、未来数据及跨账户起点分别处理；无效起点不会掩盖
有效私有流。起点报告指向丢失原文时记为损坏，不能当作从未采集。

固定路径逐层检查 UID、权限、普通单链接文件，目录读取及输出各有
1000 文件/64 MiB 预算；私有日志沿用 200000 条/128 MiB 上限。
写者锁防止同时改最新指针，摘要记录按内容地址只追加到 `observation-views`。
输入库不创建、不复制、不修改；无法读取原私有链则本次不发布，旧副本按原时间过期。

已有 `tools.demo_oms_status_publish --kind executor-observation` 负责校验并复制
小型展示记录到独立研究缓存，不接触原 SQLite 或凭证。旧副本不被时间回退覆盖，
源/目标目录不能重叠。复制权限必须由实际部署提供，命令本身不创建特权或切换身份。

Console 从 `data/cache/binance_demo_executor_observation` 读取，新增精确
`executor_observation` 合同；TypeScript 解析器和 API 合同测试同步。
120 秒无新汇总则标历史；起点 30 秒、流 120 秒、驻留 60 秒的观察年龄在前端
另行展示。保存的 OMS/撤单终态继续作为历史事实，不能因时间老而自动重发。

Studio 增加“执行侧观测”：六项原记录、缺口和重复数量、刷新失败及过期状态、
可展开的来源摘要；手机使用单列卡片。研究端原有账户采集保持独立展示。
所有来源认证、提交、现金闭合和经济权限标记均为 false；有记录不代表交易验收。

## 使用位置

实际固定身份和原数据库安装后，以执行身份运行：

```bash
python -P -m tools.demo_executor_observation --source-commit <已验收源码完整提交号>
```

由部署提供的只读发布身份把 `observation-views` 复制到研究缓存：

```bash
python -P -m tools.demo_oms_status_publish --kind executor-observation \
  --source-dir /var/lib/quantos-demo-executor/observation-views \
  --output-dir <研究状态根>/data/cache/binance_demo_executor_observation
```

以上为接线入口，不是已安装服务的声明。没有在实际目录生成签发私钥、批准、
人工身份或订单，也没有从研究缓存反向导入执行来源。
