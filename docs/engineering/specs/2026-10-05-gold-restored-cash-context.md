## 原缺口与接线

原整组恢复关闭只消费签发—执行和 retention 镜像；执行组件在没有
完整执行状态、原收据日志和实际分区证据时，明确保留现金未重放状态。
历史持仓读者只有原持仓切片入口，未给恢复后的现金组件提供完整原书。

`HistoricalBook.open_execution` 通过原 SQLite/WAL 只读快照器取得
dispatch、recovery、OMS 和 user-stream，沿原 `_state` 核对终态和全预留
覆盖，重验每份原签名。完整 OMS 仍须匹配原事件投影。原路径和归档索引
共同定位私有恢复日志，不修改 plan/import 中保存的绝对路径，也不打开
已不可用的旧目录。原 V2 reducer 重建上下文；已安装 BTC/Gold 分区时
沿原分区和两种抵押品分别重放，不合并现金。没有实际公件句柄不能推断
分区不存在，返回数据不会授予恢复执行或交易权限。

整组关联增加 V2 报告，实际 Root 只消费三个原密封 peer 的同 cut 恢复。
新的现金读者在任何 CLOSE 前，沿原组件和 `build_from_records` 重复报表
现金核对；全部日志、book 和恢复原件保持到整组退出复核。报表使用原
`opening_at_ms` 为上界，晚于该 cut 的实际可用输入拒绝。旧组件调用没有
cut 参数时保留原行为；旧 V1 维护结果合同保持，V2 必须包含相同源码、
账户、cut 和自洽完成状态的现金报告。

实际 Root 首轮暴露恢复档案按原设计不含 `.git`，报表重放需验证原策略
源码控制信息。修正复用原 `_semantic_shadow` 和 `_prepare_source_shadow`：
从原密封 peer 的源码附件核验 Git bundle，在私有临时副本中创建 Git
控制信息后消费原组件。恢复原件不补写 `.git`，计划路径不重写。源码
包、私有树与原 book 保持到所有 worker 关闭复核，退出销毁临时副本；
缺附件或原 bundle 改变拒绝。未开始、无执行历史和持仓未平时不得携带
已重放的 episode 或 partial，完成报告的状态与实际组件相匹配。

## 完成状态与限制

`reported_cash_replay_verified` 只在原报表输入、唯一账本重放及原反馈
确实齐全时成立。`technical_cash_components_verified` 还要求全部原现金
采集组件完成，且没有原组件 partial。没有历史、仍持仓、未开始和部分
材料分别保留。原原生案例的报表已完成重放，但长期现金采集仅
`OPENING_RETAINED`，因此报告保持 `PARTIAL`，不把它改为完成。

`cash_reconciled`、整个 writer 屏障、整组业务连接、whole_set、经济权威
和下单权限继续 false。该读者不收集私有账户数据、不写原状态，不重建
第二套现金账本。现场同 cut 停写、长期数据/独立准入、获准 Demo 和
完整端到端验收继续属于原 F1–F5 收尾条件。
