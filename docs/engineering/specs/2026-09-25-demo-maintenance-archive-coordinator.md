# 窗口证据到受限归档与回滚

新增 `demo_maintenance_staging` 与 `demo_maintenance_grants`，并接入 `demo_maintenance_window.stage_evidence / execute_archive / recover_archive`。这些是受控管理员流程的开发接口，没有现场CLI、凭证、交易签发或生产执行。

## 最终行为

- 暂存仅接受本窗口已完成且子进程已退出的准备记录。重新验证发行版/公共身份配置、执行根身份及五份实际输入；流式复制备份并核对前后文件身份、大小、摘要和私有所有权。计划候选必须被备份覆盖，引用与选中数量绑定；成功最后才写root所有的暂存回执。
- 维护许可绑定暂存回执的明确批准摘要、窗口、批次、执行UID、发行版、原始根身份、输入摘要、boot和活控制端；封印描述符600秒内有效。没有任意JSON签发入口，也不构造HUMAN、交易授权或签发密钥。
- PREPARE完成后，根协调器独立读取事务清单与许可回执，核对实际摘要和首个派发摘要，并在APPLY前持久保存事务绑定。APPLY失败或派发后异常只尝试一次ROLLBACK；回滚失败保留暂停状态，不能声称服务恢复。
- ROLLBACK使用原已绑定的事务清单与回执，不要求大备份仍在。恢复入口先验证批准摘要，再检查/停止确属本次派发的未退出子进程。只处理已知APPLY/ROLLBACK，不把重启当成再次归档授权。
- 成功归档或完整回滚后，外层操作流程仍须调用既有restore，检查配置和进程并恢复原active单元；未自动恢复之前不返回services_restored=true。
