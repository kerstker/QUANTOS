# 黄金轮次丢失终态后的预算恢复

复现：Runner 已记录 error，但 FactoryStore session 仍为 RUNNING 时，原调度器直接
将轮次结算 FAILED。若进程在模型结果落盘之后、试验镜像写入之前退出，已知候选可能
没有进入下一轮排除列表。新回归先失败，确认此预算交接缺口。

修复保留原 RESERVED 轮次。仅在队列具有明确终态且工作流尚未结算时，原调度器
提交一个独立、幂等的 gold_factory_recover invocation。该入口复用原工作流锁和
材料复核，只允许已存在的尝试目录；恢复路径不会调用模型。

恢复完成后记录原 run_id 和 recovery_run_id，再结算原轮次。原 Runner 的 error 不改写。
恢复失败或证据未知保持 WAITING_GOLD_RECONCILIATION，不另建重试身份或推进下一轮。
暂停/停止 campaign 不派发恢复，已有其他排队/运行任务时也不增添隐藏队列。

## 验证

六组联合 **130 passed，1 skipped**，含实际子进程在模型提案完成后 os._exit(77)，
父进程确认 returncode=77，随后通过原队列恢复同一候选、完成正式试验并从下一轮排除。
模型响应为隔离测试传输；新模型调用被显式禁止。队列失败记录使用独立测试任务模拟，
因此不把此测试说成完整 Runner 主进程崩溃的现场验收。

还覆盖无可恢复证据时只派发一次并保留预留、暂停禁止恢复、原有多轮预算/失败计数、
单试验恢复、Runner 边界及 Console API。工具/测试 Ruff、注册文件 E9/F821、治理和
仓库卫生通过。未部署，未运行 canonical 全量验收。

## 明确边界

本增量处理的是“队列已记录终态，工作流终态缺失”。若 Runner 主进程整体退出、
数据库仍显示 running，不能仅凭旧状态文件或超时推断进程死亡；当前仍等待明确的
运行所有权/进程存活证据，不自动将它改为 error。该层恢复与进程强杀、断电耐久性
仍需后续验证。全局跨 campaign 预算、独立 OOS/准入及黄金 Demo/资金闭环未完成。
