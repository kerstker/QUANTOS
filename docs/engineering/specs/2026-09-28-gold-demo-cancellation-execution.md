# 黄金 Demo 撤单执行交接

## 实现与证据

三个黄金原订单撤单回归先在原订单批次默认 BTC 校验处失败。协调器现从原派发预留的签名信封选择协议，签发器从独立策略选择对应撤单版本；原签发历史、账户、部署、原订单及查询摘要约束保持。原 DELETE 编码和传输显式接受黄金版本，默认仍只接受旧 BTC 范围。

隔离测试经过实际原提案、临时 Ed25519 签发、SQLite 派发/撤单日志、协调器和模拟 HTTP，覆盖撤单响应、超时、撤单时已全部成交。每个批准只尝试一次，发送前持久化 claim；结果始终要求原编号查询恢复，不写 OMS 成交、现金或新订单。真实凭证、来源托管检查与网络使用 fixture，不能视为独立部署验收。

新增 DEMO_GOLD_CANCEL_STATUS_V1 状态投影；后端和前端均拒绝黄金/旧 BTC 版本互换。控制台撤单表补显示合约名称，成功响应仍不显示撤单或资金闭环完成。

## 验证

- 七组后端相关测试：163 passed、1 skipped，包括现有 BTC 撤单、会话、签发器、黄金签发器及控制台 API 合同。
- 前端撤单组件：4 passed。新黄金显示回归先失败，补合约列后通过。
- Ruff E9/F821、治理扫描 698 文件零违规、仓库卫生通过。
- 一次默认 Ruff 检查发现 193 项，包括原有紧凑代码格式和未使用导入；没有宣称全量 lint 通过或自动格式化无关代码。
- 一次前端命令误在仓库根执行，npm 临时获取 Vitest 5 后因缺少应用别名配置失败；随后使用应用目录已有 Vitest 4.1.10 通过。根 package.json/package-lock.json 无改动。
