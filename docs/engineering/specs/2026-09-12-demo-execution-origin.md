# Demo 执行起点的完整账户范围

2026-09-12。承接[执行实施顺序](../plans/2026-09-12-demo-execution-completion.md) D0。
本批增加真实只读采集、离线校验、Console 接口与 Studio 展示；没有提交订单、
安装签发密钥、启动新的执行服务或改变经济准入。

## 解决的缺口

原账户 V1 采集只覆盖普通挂单，账户命名空间由后续导入材料声明；空仓目标的保证金
模式也不能仅靠已有仓位推断。新增独立 `DEMO_EXECUTION_ORIGIN_V1`，旧 V1 输入、
哈希与历史记录不变。一次读取凭证，在同一命名空间完成 16 次固定 GET：

1. 时钟、账户配置、账户余额、合约配置、全部仓位、全部普通挂单。
2. 全部条件挂单、目标规则、账户费率、风险档位、标记价格与盘口。
3. 再读合约配置、账户余额、账户配置和时钟。

公共请求不携带凭证。普通和条件挂单查询都不按目标合约过滤，防止漏掉其他待触发
订单。响应只保留约定字段；大订单编号保留十进制字符串。无网络默认态不读取凭证。
单次请求 10 秒、子进程 115 秒；本批不自动重试起点采集。失败保留已成功输入、
失败类别与响应摘要；拒绝的服务端时间也保留供诊断，绝不采纳为合格时钟。

完整采集可以形成“观察到目标币种空仓”的诊断，仍要求账户模式、目标全仓模式、
同币种仓位、普通与条件挂单、自由钱包、规则及行情时间通过检查。
最早输入超过 30 秒即过期；历史采样一致性与当前过期分别表达，不把过期误写成
“采样期间账户发生变化”。缺失仓位统计显示未知，不能替换为零。

原始文件按内容哈希追加保存并同步落盘；`latest.json` 只是读取指针。Console 只读
这些保存记录，不接触凭证或场所。前端显示计价范围、旧仓位数、两类挂单、源码摘要、
过期和失败；手机金额去掉无意义尾零，展开项保留原始精度。
