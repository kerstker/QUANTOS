# 黄金配置命令入口与确认用途一致性

前一增量已让功能控制器接受黄金配置，但实际 setup 命令入口仍只生成 BTC 配置，且 `operator_confirmation` 对黄金规格返回旧 `DEMO_FUNCTIONAL_TEST_ONLY`，与材料验证器要求不一致。确认提示还错误显示 USDC。

`tools/demo_operator_setup.py` 现在接受显式 `--symbol XAUUSDT`，旧默认仍为 BTCUSDC。首次与确认后的刷新采集均向原执行 UID 的固定子进程传递同一合约；返回文件必须位于对应的 execution-origins 合约目录，加载后再核对实际品种。不存在使用 BTC 路径冒充黄金观察的回退。

批准用途由同一函数提供给确认和校验路径；黄金返回 `DEMO_GOLD_FUNCTIONAL_TEST_ONLY` 并显示 XAUUSDT / USDT 限额。原 TTY、sudo 操作员身份、精确规格摘要、有效期、首次登记、原 stop 状态和原安装器检查保持。未登记时仅输出未签提案，不生成安装材料或启动服务。

验证先复现 CLI 不接受品种、黄金确认用途不匹配及运行采集不接受品种参数。修复后黄金/旧 setup 与功能周期三组 35 passed，修改文件 Ruff E9/F821 通过。测试使用临时目录、模拟 TTY/身份和子进程；没有对真实账户执行该命令，也没有生成实际批准、安装或更新密钥登记表。

这只完成首装入口的黄金接线，不等于现有 BTC 部署可以直接升级。已有安装仍拒绝覆盖；旧摘要记录迁移、后继配置、跨日/账户恢复入口、自动反馈导出交付、真实 Demo 和经济准入继续待完成。没有将功能验收策略自动替换为已批准的研究候选。
