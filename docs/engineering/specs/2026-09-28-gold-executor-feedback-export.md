# 执行 worker 从原记录导出整轮反馈

原整轮导出函数需要调用方手工提供每批 prepared 记录及窗口。新增 `tools/demo_functional_worker.export_feedback` 和原 worker 的 `feedback` 操作，供受控协调器调用；沿用原执行 UID 子进程、维护互斥及准备锁，不新增网络采集或签发路径。

## 材料重建

- 验证固定执行根、账户和周期目录；读取已保留的黄金 scope，要求原持仓已平、所有恢复状态和 OMS 已终结。
- 从原上下文 sources、dispatch 预留、恢复计划及原 proposal 文件重建 prepared，核对账户/订单/上下文；不接受调用方挑选订单、路径、窗口或余额。
- 按 scope 的原策略选取 2–3 个原生批次。窗口从各次原始账户观察完成后开始，延伸到下一批起点，末批覆盖实际现金查询末端；保持原 150 秒单窗口限制，超限拒绝。
- 调用原整轮反馈构建器，重新核对每批查询、私有成交、原现金链和候选身份。候选身份仍须匹配所有原签名策略，不允许缺失身份冒充已归属。
- 发布前重新核对原状态、私有流、现金捕获和周期 scope 未变；在周期私有目录以原不可覆盖写入机制保存反馈。返回内容摘要和文件摘要，不直接修改研究配置或发单。

## 集成验证

原黄金研究/开平仓集成测试改为由 worker 从原记录选择批次并导出，再由真实 FactoryStore/JobQueue 消费保存的反馈字节，完成下一候选及新 TrialLedger 记录。重复导出返回同一文件且原 dispatch/recovery/OMS 不变；错账户、缺少候选身份和后到原开仓 UNKNOWN 均拒绝。测试把凭证读取和 HTTP 替换为立即失败函数，确认导出不调用二者。

运行端 UID/custody 和已打开 stores 使用隔离 fixture；保留文件的目录/文件权限实际检查。首次测试暴露 fixture 缺少 resident-recovery 目录及过宽父目录权限，按安装布局补齐测试环境，没有放松生产检查。四组 27 passed，追加目录保护后黄金 5 项复验通过；修改文件 Ruff E9/F821 通过。

## 交付范围

这是受控导出能力和真实队列的隔离联调。测试辅助器仍负责把导出文件送到研究目录，生产控制器尚未自动调用导出、跨 UID 交付或登记后续研究轮。没有部署、读取真实凭证、修改实际批准或交易。

当前功能周期最多三批、每批有成交及同日现金窗口等现有约束继续生效；包含未成交重试、跨日整轮反馈和非原生账户恢复前缀仍需单独验收。既有 BTC 部署和旧摘要记录迁移、真实黄金 Demo、稳定监控、独立经济准入以及完整工厂验收仍未完成。
