# 黄金整轮反馈：保留未成交减仓批次

## 问题与实现

`build_roundtrip_feedback` 原先要求每个批次都有正成交量，因此在开仓成交、第一次 IOC 减仓终态为零成交、第二次获准减仓完成时，反馈会被 `FEEDBACK_ROUNDTRIP_FILL_REQUIRED` 阻断。

调整为开仓必须有成交、后续减仓合计必须存在成交；所有批次仍必须通过原 `prepare_resolution`，全部原日志进入同一 `project_cash_chain`。零成交批次不会被丢弃。现金匹配、最终零持仓、时间可用性和派发快照检查保持。该导出器不签发重试、不发单、不授予经济资格。

## 验证范围

新增编排层回归使用受控 resolution/cash 适配器，验证三批次原顺序及未成交记录保留，并验证未知订单、零成交开仓、全部减仓零成交、现金未知、非零结尾及派发变化拒绝。修复前合法场景失败，现金/持仓/快照反例也被提前的成交限制遮挡；修复后七例通过。

与原黄金开平仓/实际反馈导出/下一轮研究队列、反馈消费者及研究进程边界联合：31 passed，保留一条 Starlette/httpx 弃用警告；Ruff E9/F821 通过。

新增三批次回归是编排级测试，不证明真实私有回执下的三批次现金连续性。原两批次集成回归仍通过。三批次原始回执集成、生产控制器调用、跨 UID 交付、部署和真实 Demo 持续运行仍待完成；未修改实际授权、凭证或生产状态。

## 原始回执三批次联调续验

新增 `tests/live/gold_empty_reduction.py`，并将原黄金私有回执全链用例增加 retry 场景：第一轮正式研究身份 → 原风险提案/隔离签发 → 开仓成交 → 较高 SELL 限价的 IOC 零成交 EXPIRED → 新限价减仓成交 → 原查询/OMS/现金链 → worker 固定目录整轮导出 → 原 campaign/JobQueue 下一轮研究。

三次签发的隔离测试预算在首次签发前固定为三次、总名义额 400；不修改生产授权，不删除原预算消费。联调最初分别被原重复指纹门和原累计签发预算拒绝，说明两道门仍有效。场景明确使用两次不同限价提案，并额外验证同价同量快速重复减仓仍被原风险门拒绝，不将“重试”作为绕过理由。

三个批次、两笔成交，最终仓位零、现金 4999.98、费用 0.02、残差零；零成交批次原预留编号、EXPIRED 和数量 0 出现在实际导出中。对该中间批次追加原编号 UNKNOWN 查询后，直接反馈与 worker 重导出均拒绝。原两批次场景继续保留。四组联合 22 passed；两份测试文件 Ruff E9/F821 通过。

本续验替代上节“三批次原始回执集成待完成”的限制，但网络、私有数据、模型和签名均为隔离 fixture，原生产控制器调用、跨 UID 交付、部署和真实 Demo 持续运行仍未完成。此次仅增加集成验收代码，没有改运行权限或生产状态。
