用户要求继续完成 Demo 接线。本批把上一批带仓位初始化能力接到既有回执日志、离线导入工具、

## 本次完成

新增冻结输入版本 `DEMO_EXECUTION_REPLAY_V2`。旧 V1 仍要求初始空仓，旧日志不原地升级。
V2 的 `opening` 包含原始规范化账户快照、快照摘要、声明账户引用、逐仓精确成本及来源摘要、
其他合约规则。账户引用必须与固定订单引用相同；同一保证金币种的全部已有仓位必须纳入。
USDT 和 USDC 分别建账，其他币种的数量明确列出，不混用余额。

`services/research/demo_opening_projection.py` 负责绑定与缺项判断，
`services/research/demo_execution_journal.py` 继续负责不可变输入日志和重建。
只有声明输入完整且核心账本支持时，才使用 `OpeningLedgerState` 与原来的
`ReportedFillReplayEvent` 重放目标订单；没有复制费用、持仓或资金费算法。

- 起始钱包和目标持仓必须与绑定快照一致；截止时间必须早于回执窗口，间隔最多120秒。
- 缺精确成本、缺合约规则、账户变化、双向持仓、多资产抵押、已有普通挂单及数量网格不支持
  都有具体原因；不猜测成本或规则。目标合约规则可明确为缺失，此时不创建现金投影。
- 同币种其他仓位需要精确成本和规则；逐仓资金从总钱包中分配一次。
- 开仓浮盈亏不计入本段收益；重复导入、重启和只读恢复不重复收取回执费用。
- 修改成本来源、快照或其他冻结字段需要新日志；旧查询结果不能用于修改后的起点。
- 修复 Demo 数量口径：基础资产数量不能再乘额外合约倍数，拒绝非1的声明倍数。

`tools/demo_execution_replay.py` 新增 `--opening-capture`、可选 `--opening-basis`、
`--opening-contracts`。它把新绑定完整存入现有日志，不能覆盖输入文件、给既有日志重新贴起点，
或将缺项变为成功。默认离线，无网络、凭证或下单入口。

API 的 `execution.report.opening`、TypeScript 合同、解析器及 Console API 回归同步。
前端显示回放起点、钱包币种、同/其他币种仓位、缺成本/规则数量、逐仓输入与来源。
尚无订单回执时直接说明，不显示成已经导入成交。已有空仓回放说明仅用于V1。
