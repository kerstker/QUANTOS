# 黄金功能周期的运行范围与现金展示

## 现场入口对应的代码缺口

整轮反馈隔离联调完成后，检查原驻留周期发现：控制器只接受旧 BTC setup，worker 的 settle/context/reconcile 和账户现金路径默认 BTCUSDC；账户历史采集和现金状态展示也限制 BTC。单独调用黄金反馈函数并不能使该周期运行。

本增量沿用原功能控制器和 worker：

- 控制器接受显式黄金 setup，核对 spec/profile/policy 的同一合约，并将黄金合约随首次 cash 操作传入。
- worker 将 `DEMO_GOLD_CYCLE_SCOPE_V1` 固定到原周期目录，后续持仓/现金检查读取相同范围。旧 scope 仍只代表 BTCUSDC；黄金只接受 XAUUSDT，并可保留内容绑定的 gold-research 策略标识。记录本身不授予批准，订单仍须经过原签发/风险链。
- 原账户现金路径从保留的原始账户观察确定合约，两次历史采集和后置观察须同账户、同合约。黄金执行侧流水新增独立普通/跨日格式，旧 BTC 格式拒绝黄金。
- 现金状态输出新增 `DEMO_GOLD_CASH_CHAIN_STATUS_V1`，保持原金额与未知状态约束。控制台 API、TypeScript 合同和前端单位同步支持 XAU，避免黄金账本已核对但展示保存失败。

## 验证

黄金控制器入口先在 CONFIGURATION 拒绝；黄金 statement 两个合法场景先在范围校验失败；worker 真实多批账本核对随后在现金状态的 BTC 限制失败。逐项修复后：

- 控制器、worker、账户现金、statement、报告恢复、组合控制器、现金状态及控制台 API 合同：159 passed、1 skipped。
- 前端现金链组件：5 passed；TypeScript typecheck 通过。
- 修改的 Python 文件 Ruff E9/F821 通过；治理扫描 700 文件、0 违规。

控制器子进程和签发操作使用测试替身；流水采集使用合成私有传输；worker 现金测试真实重放日志但持仓读取采用测试上下文。新增黄金两次流水采集可进入原账户恢复并零残差，未把人工平仓归为系统自动成交。没有执行实际凭证读取、安装、服务切换或订单。

## 仍需接线

操作员 setup CLI/首装采集仍默认 BTC；已有 root 安装和旧账本摘要记录不能静默迁移。跨日主入口和账户修复主入口尚未完成黄金路由。本增量不是完整驻留验收：整轮反馈的受控导出、研究侧自动交付、实际黄金配置、真实 Demo 和稳定运行仍需完成。先前整轮反馈联调结论不扩展为部署完成。
