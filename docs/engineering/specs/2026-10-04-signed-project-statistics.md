## 原问题与现在的行为

原项目统计能够沿原记录计算 DSR、CPCV、PBO 和固定基准，但该报告未进入
项目来源签名、结果签名及原评审库的共同身份。V2 原评审因此只能保留
统计和基准核验尚未完成；独立结果签名不能替代本地复算。

新 `QUANTOS_PROJECT_RESEARCH_STATISTICAL_EVIDENCE_V1` 留存原政策、完整试验
cohort 和报告。消费者只从原项目 cut 的原输入、登记、原生账本及结果复算，
不接收外来净值曲线。基准必须是同源、同数据、同网格的原生运行，政策摘要
必须已在原运行前的 evaluation core 中绑定；不能给旧运行补登记时间。
报告必须与原核完全相同，不能删失败或未完成尝试、替换同名候选、改指标，
或把未来评审时间放入当前消费。

统计材料使用新的项目 snapshot/envelope/statement/assessment V3 和 facts V4。
V3 的独立签名域绑定完整 cut、原候选与 native trial、完整 source manifest、
统计材料摘要及复算 projection；来源核验增加政策预登记，结果核验增加
统计重放，证据角色必须同时引用原项目与统计材料。V2 签名不能验证 V3，
原 V2 格式、签名域及读者继续保持。

固定读者新增固定文件 `statistical_evidence.json`，全部原项目、源码、独立
trust 和材料仍在同一保留读集合内。实际执行的统计/投影/原核/合同模块必须
来自所选择的受验源码根；另一个内容相同的源码树不能选择当前执行代码。
双读、物理身份复核和最终时钟检查保持。运送材料不能指定路径或自选信任根。

原评审库使用新的 artifact V3 及独立行身份/内容域，仍沿原 evaluations 和
唯一 audit intent 的事务持久化。没有新平行数据库、准入布尔开关或搜索
活动。冷读核原统计；再次使用核当前 source/trust/原件，原 cut 之后只允许
已验证的评审元数据增量，新试验或 OOS 活动不能复用旧签名。

统计 FAIL 即使遇到独立签名 PASS 也为 REJECTED。统计 PASS 仍缺独立锁定
OOS、真实成本风险及最终准入证据时保持 INSUFFICIENT；预筛 PASS 保留其
原有限意义。promotion、submission 和 economic authority 均未开放。
