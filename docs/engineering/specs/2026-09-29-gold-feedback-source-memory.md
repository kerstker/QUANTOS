# 执行反馈续轮携带原实验诊断

执行反馈创建另一研究计划时，原调度会排除已用候选，但 campaign_memory 只读取本计划及同采集组，导致模型没有收到反馈来源实验的诊断。原真实 JobQueue 回归增加请求断言后，先复现第二轮 research_memory 为 None。

原 reserve_campaign 完成反馈摘要、时间、输入和原 trial/candidate 核对后，将已核对的来源 attempt 交给现有记忆查询。查询加入该来源实验，继续在同一事务冻结、最多六条、按已知时间排序；模型调用前复用原档案验证。普通独立计划仍不共享记忆。没有将资金反馈内容加入模型，也没有把 source_verified=false 改成可信收益。

原队列验证：首轮实验→反馈触发新计划→第二轮模型实际收到原 trial/report 身份；反馈文件损坏和原成本报告损坏分别阻止第二次模型调用。六组 43 passed，保留 Starlette 弃用警告；E9/F821 和相关 diff 检查通过。回归中的后续决策时点改为不早于会话完成时间，保留生产的未来事实拒绝。

本增量仅开发工作区，模型及执行反馈为测试替身；未修改在途 a232 冻结源码，未部署。它补齐原实验诊断，不代表成交/成本偏差已能指导模型，也不代表真实 Demo 闭环完成。
