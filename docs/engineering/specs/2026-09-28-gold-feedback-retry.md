# 已完成周期的反馈只读重试

`tools.demo_functional_cycle --feedback-only` 与下单 resume/recover 模式互斥。入口核对固定源码、执行/签发登记镜像、policy 的登记/发布绑定、已安装 spec、研究身份、原 claim、周期结果和原 task 摘要。只接受同版已完成且现金核对为真的黄金研究周期，并要求 task、policy、研究身份的策略编号一致。

原交易授权可以过期；这里不调用 current_key、不续期批准、不走 task executor。原 worker feedback 重新从当下原始记录构造反馈，之后调用固定交付入口。不存在直接重发旧反馈文件而跳过原证据复核的快捷路径。

原结果文件保持不可覆盖；新结果追加到 feedback-results。失败只记录安全状态，返回2；配置/原结果不满足要求返回3。周期锁和64条反馈历史上限保持有限操作，不形成无限自动循环。实际自动重试调度与发布登记仍待接线。

新 CLI 回归先因参数不存在失败，实现后四组45 passed，Ruff E9/F821 通过。测试覆盖成功/失败交付、授权过期后的只读重试、原结果字节不变、执行器调用禁止、现金未完成时不启动 worker、诊断不泄露。子进程及root身份为隔离替身，未进行实际生产重试或部署。

限制：入口当前核对当前安装周期的原 result.json；后续 recovery-results 才形成完成证据、切换发布版本或切换安装周期的情况尚未覆盖。实际后台调度、自动下一 campaign、独立经济准入及真实Demo持续验收仍待完成。

## 恢复后完成证据续补

后台自动重试前核对发现：原结果失败、后续 recovery-results 成功时，反馈入口只看原 result.json 会永久拒绝；原 recover 入口也仍限定旧 BTC setup schema。两项新回归分别因缺少选择器、黄金恢复返回3而失败。

现 feedback_completion 在周期锁内读取受保护的原结果及最多32条恢复记录，逐条核对内容摘要命名、周期、源码版本、原源码版本及非未来时间；选择最新结果，同时间矛盾拒绝，后到失败不回退旧成功。选中的完成结果还通过原现金/零持仓/成交数显示合同验证。原失败结果不改写。恢复入口接受明确黄金 schema，核对原 task/policy 市场及研究身份，仍不得发单或续期。

四组51 passed；追加反馈 CLI 场景证明原失败字节保持、恢复完成后实际触发导出/交付、后到失败再次阻断，控制器专项28 passed。Ruff E9/F821通过。身份/子进程为隔离替身，未进行现场恢复或部署。

此前“只接受原 result.json 完成”的限制已解除；仍限定同版当前安装周期，跨发布版本/旧周期的回放尚未覆盖。后台 timer 及维护暂停范围需一起接入，未安装或启用自动任务。

## 后台轮询幂等入口

新增与其他运行模式互斥的 `--feedback-pending`。原完成结果（去掉 research_feedback 回执字段）的摘要作为 completion_sha256，首次自动交付及只读重试都将其写入受保护反馈回执。后台入口仍先核对安装、claim、最新完成证据和 task，然后逐条核对最多64份反馈回执的内容摘要命名、周期/源码/时间；只有最新匹配完成摘要的成功回执能使本次返回 RESEARCH_FEEDBACK_ALREADY_DELIVERED，不启动 worker、不追加文件。

较新的失败回执不会被旧成功掩盖；不同完成摘要、未来/损坏/矛盾回执不能跳过。显式 --feedback-only 保持重新核对原执行证据的语义。初版无 completion_sha256 的回执不能作为后台去重证明，需要一次正常导出交付。

新增回归先因缺少回执选择器失败；实现后控制器/交付/worker三组45 passed，追加 CLI 场景验证 worker零调用和文件字节集合不变，Ruff E9/F821通过。尚无现场后台进程。

核对发现维护服务列表是固定范围，对应全部单元须已安装并可验证；直接添加一个独立 timer 会遗漏运行任务排空，直接扩展列表又可能令旧安装维护预检失败。因此本次未安装或生成可启动 timer。后续须将后台单元登记、旧安装兼容、暂停/恢复和部署材料作为同一交付验收，不能仅靠 ConditionPathExists 宣称维护窗口安全。
