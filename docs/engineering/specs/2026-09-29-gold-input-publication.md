# 黄金采集资料到正式研究输入

## 功能与实际边界

原公开报价捕获、成交信号回放和成本输入装配器已存在，但没有正式任务将结果交给持续研究计划。新增 `gold_prepare_input`，从原JobQueue/RunRegistry执行，发布至生命周期页面已有数据选择目录；新建研究页面可启动此任务，黄金计划页面链接到该入口。

任务参数仅为1–1000的 `attempt`，同时作为快照编号。固定读取状态根下 `data/cache/ai_factory/gold-preparation/<attempt>/` 的三份材料：

- `quotes.json`：原 `GOLD_PUBLIC_REPLAY_CAPTURE_V1` 公开报价捕获。
- `signals.json`：原 `GOLD_SIGNAL_REPLAY_INPUT_V1`，包含成交、窗口、区域和决策时点。
- `template.json`：原 `GOLD_COST_INPUT_V1`，仅复用其显式plan、initial_collateral、costs和limits；行情、规则、资金费和容量全部由当前quotes重新装配，源码身份取本次运行。

原信号引擎先检查窗口完整性，再由原公开输入适配器处理报价覆盖和因果对齐。成功后原子发布 `gold-inputs/<attempt>.json`，原文件摘要即页面选择和campaign使用的摘要；并保存 `<attempt>.metadata.json`，绑定三份来源字节与源码。相同请求重放复用相同内容，变化请求不能覆盖已占用编号。元数据先落盘，快照发布失败时不会出现部分JSON；重试可完成相同内容的发布。

这是已有采集资料的离线交接，不是持续联网采集服务。原始采集与模板仍需先存在，公开来源/账户实际成本未认证；无自动区域发现、无独立经济准入、无交易动作。持续生成这些输入的采集编排仍是主线缺口，不能将本任务等同于完整数据自动化。
