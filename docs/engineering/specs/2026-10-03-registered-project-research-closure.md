## Native project records

original input before original registry/provenance registration, PLANNED/RUNNING
events, and the invocation witness. They reuse the original producers and native
trial ledgers. A second search using the same definition is a distinct attempt;
the original deterministic technical result ID may repeat. It never deduplicates
native trial IDs, failed attempts or unfinished work.

The producer resumes publication of a complete durable report without recomputing
it. An invocation without a complete report or explicit failure remains UNKNOWN.
Report publication/readback failures are not rewritten as algorithm failures.

`ProjectResearchEvidenceReader` reads the original DB/WAL into private copies and
retains all managed run originals, original trial and validation-receipt chains,
registry search/provenance/OOS history, and evaluation activity metadata/links.
Unmapped legacy records and incomplete finalization remain explicit. Native ledger
global sequences are checked separately, never concatenated or renumbered.

bindings. It recomputes chains, population counts and missing-work classifications.
It cannot prove filesystem completeness from a transported hash alone. The fixed
reader establishes the actual files; independent attestations remain separate.
Evaluation metadata/link verification does not recompute every evaluation body.

receipt persistence must explicitly distinguish the retained signed cut from the
current cut. It must not omit activity merely to keep a digest unchanged.

## Evaluation timing and independent consumption

An optional V2 technical-run plan binds a strict evaluation core before any plan
or input is written. The core identifies the input, source, dataset, exact native
cohort, budget, sample/splits, selection and metric policies, benchmark, termination
policy and OOS-access evidence references. The original PLANNED/RUNNING rows bind
the core hash as their validation-policy identity, and original provenance binds
the complete run plan. A completed V1 attempt cannot acquire a later core.

Historical sample time is separate from registration time. BACKTEST permits a
historical sample with today's registration; FORWARD declarations retain the
registration-before-window rule. No old timestamp is fabricated. The current V2
producer supports one technical invocation per core. Gold V1 records remain
readable and cannot acquire a retrospectively fabricated evaluation plan.

The new project signature domain binds the complete cut, selected invocation and
native trial, and the source manifest. A fixed reader verifies the actual complete
source tree, independent pinned trust file, and project originals in one retained
read set. Consumption rereads them and checks the final delivery clock. The market
comes from the original input: a BTC technical run cannot be labelled XAUUSDT for
an authority key scoped only to gold.

Evaluated technical results reuse the original manifest/result identity checks
and the original Decimal cash/statistics calculation. Native economic claims are
unchanged. Missing OOS access proof, benchmark/multiple-testing review and independent
risk replay remain explicit limitations. Even valid signatures produce only
INSUFFICIENT or REJECTED; they do not approve promotion or order submission.
