# 黄金账户恢复、跨日与时钟边界

## 原执行路径继续接线

`tools/demo_reported_recovery.run` 与 `tools/demo_day_checkpoint.run` 现在接受明确的黄金范围，原默认 BTCUSDC 保持。功能 worker 从已保留的周期范围传递合约，不从最新行情或任意新账户观察推断品种。

账户恢复在读取保留恢复结果、采集或投影前检查原 dispatch 预留的账户和合约。它必须允许未知发送状态进入原编号查询/恢复，因此范围检查读取原 dispatch 记录，不调用仅允许已恢复状态的提案准备函数。实际校验仍由原恢复计划、现金账本及 OMS 完成。人工平仓归属、流缺口和非自动周期标记不变。

跨日入口从同一黄金持仓上下文建立原检查点，再通过实际风险消费者重读；没有重置本金、累计损失、容量消耗或新增发单权限。

## 验证

扩展已有签名/未知发送/查询/账户恢复 fixture 的黄金场景，使用临时密钥与合成私有数据。工具级测试验证原真实 dispatch/recovery/OMS：

- 完整黄金证据只投影原系统订单一次，保留人工平仓及两处流缺口。
- 投影后保存 outcome 中断，续作不重复采集、成交或订单。
- 错账户、错合约、来源变化、第二次流水不一致均拒绝。
- 黄金跨日检查点写入后可原样重读；执行状态变化拒绝保存检查点；本金、账本摘要、容量和原损失保持。

三组恢复/跨日先通过 30 项，追加品种拒绝并联测原恢复、功能 worker/控制器后 59 passed。测试中的两个合成账户来源最初未对齐，修正了 fixture 的账户及各私有读取引用；没有放松生产账户检查。

## 黄金 V3 时钟遗漏

检查继续交易的时间边界发现，`prepare_opening` 只为旧 BTC V3 回执应用场所时钟边界，黄金 V3 被误用为本地同钟。正负 1000ms 时差两回归先失败：黄金报告缺少 `clock_boundary`。

现复用原 `CLOCK_SCHEMAS`，黄金 V3 的期初账本时间同样采用保守场所上界，保留本地观察时间和时钟摘要，仍不宣称来源认证或精确延迟。黄金现金、原期初日志、现金链、回执时钟四组 75 passed。此修复可能改变旧黄金 V3 回放摘要；未重写旧记录或沿用其旧批准。
