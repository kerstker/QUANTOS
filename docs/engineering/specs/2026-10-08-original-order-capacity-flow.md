## 同一因果时点的真实容量金额

中立合同research_capacity_flow使用唯一账本Decimal上下文。每品种由原当前数量、
原目标数量、因果估值价格、合约乘数及同一保守账户权益计算：

```
order_quantity = target_quantity - current_quantity
capacity_notional = max(abs(current_quantity), abs(target_quantity), abs(order_quantity))
                    * valuation_price * contract_multiplier
capacity_flow_weight = capacity_notional / risk_equity
```

原严格回放在决策时已核对实际订单delta等于信号目标减原持仓；执行时再次从实际
账本重算，允许使用当时实际执行价格重估，早先决策仍不能看未来执行价格。
双侧持仓及订单金额不会因为平仓后为零或换仓后仓位较小而消失。
每个决策和执行上下文保存原数量、估值、乘数、权益、容量金额和计算收据摘要；
版本MAX_CURRENT_TARGET_ORDER_NOTIONAL_V1进入原结果哈希政策。收据仅是计算
沿袭，不是原始来源认证、独立会计核验或经济权威。

## 完整风险及原拒绝边界

仅Liquidity/Capacity使用新增容量金额，其余七项继续使用原目标仓位、原收益
历史、状态和模型材料。显式流量必须逐品种覆盖原目标，有限、非负且不小于
目标绝对权重；无效流量两引擎拒绝，不静默回落到较小目标。
请求流量会要求完整输入；缺完整材料仍PENDING/零引擎，不能得到子集批准。
原zero_book守卫和既有回归保持；原当前、目标、订单均为零不会制造正流量。
实际平仓也必须通过全部九项，原模型失败仍阻断。原容量/ADV、参与率、集中度
及最低五独立下注要求没有调低。V1隔离、非权威技术状态、人工准入和提交边界保持。
