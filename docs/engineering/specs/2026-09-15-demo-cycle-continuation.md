# DEMO 周期续接与证据缺口处理

本批只处理 DEMO 开仓、回执、减仓、现金核对的主链，不扩展备份或盈利研究。
承接 [9 月 14 日实际断点](2026-09-14-demo-first-fill-recovery.md) 和
[有限周期实现](2026-09-14-demo-functional-cycle.md)。

## 实现

- 每次调用原任务执行器前，先写 root 私有、追加式、串联摘要的尝试记录。
  同目录进程锁排除并发控制器；中断后续接先查询最后一次尝试，不重复开仓。
  原 task claim、独立签发、原风险检查、最多三次尝试和原授权时限继续生效。
- `demo_functional_cycle --resume` 只接受同源码、同安装、同任务的原有效授权。
  必须有新格式尝试记录和真实开仓前现金前缀；不能把旧无检查点现场迁成可继续下单的现场。
- `--recover` 仅查询原编号并核对已有账务，允许在旧授权到期后运行接受过验收的新恢复源码。
  它不调用签发、开仓或减仓；旧安装、任务、注册表镜像和周期 claim 必须一致。
  旧格式只能从实际 root task claim 找回尝试，不能从界面阶段猜测一次提交。
- 正常延迟允许最多三次有界恢复检查；已经确定原窗口存在流缺口时立即结束本轮重查，
  发布 `EVIDENCE_REPAIR_REQUIRED`，不反复等待同一缺失输入。原驻留查询进程的调度不在本批改动中。
- 现金采集保留可独立校验的 `OPENING_CAPTURED` 前缀。续接只复用原钱包、读取身份和时钟字节，
  同账户、同采集源码且原前缀不超过 50 分钟才允许准备续接；完成时再取得真实结束钱包和两轮流水。
  原一小时窗口、分页、时钟与费用核对约束保留。结束观察增加原现金检查需要的六秒边界。
- 被拒收的金融事件进入执行账户私有的有界留存区，原 GAP 同时保留。
  只有受限金融结构和安全值词汇可以留存原文；租约、疑似凭证、未知文本或无法解析的数据只留摘要。
  预算为 256 条、16 MiB；写入失败明确记录固定诊断，不能把丢失原文当作已留存。
  留存不是自动接受事件或消除缺口，也无法补回旧版本已经丢弃的原文。
- 固定启动器对已有安装默认进入只读恢复；只接受 `--recover`、`--resume`，不能由调用者注入源码或额外选项。
  网页增加恢复命令和授权/证据缺失状态；明确证据缺口时不建议继续重复恢复。
