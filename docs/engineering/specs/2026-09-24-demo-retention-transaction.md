# Demo留存：隔离目录中的可恢复移动事务

承接[备份指针完整性](2026-09-24-demo-checkpoint-pointer-integrity.md)和
[引用检查](2026-09-24-demo-retention-reference-review.md)。
本模块补齐后续维护所需的移动/回滚机制；目前只允许离线副本用途，不是生产入口。

## 已实现

`tools/demo_retention_transaction.py`提供prepare/apply/rollback三个库函数，没有CLI、
sudo、服务操作或账户连接。明确拒绝executor/issuer/controller、/srv/quantos、
/opt/quantos保护目录及其解析后路径；同用户私有目录且同文件系统才可准备。

只接受四个容量目录中内容寻址JSON的显式名单，最多30000文件/512 MiB，
准备前逐项验证路径、所有者/权限、无链接、摘要和latest指针。latest及其目标不得
移走；apply前再次检查latest，期间更新指针会停止操作。

先持久化清单、源码目录设备/inode身份及摘要，再进行Linux renameat2 NOREPLACE
移动；fsync文件和目录。目标存在绝不覆盖。恢复时根据原路径/归档路径唯一存在
位置及清单摘要判断状态，不依赖可能尚未更新的完成计数。全部条目预检通过后
才继续移动；中断可显式续作或回滚，回滚不改变latest，不删除历史字节。

持久清单不是外部签名或权限证明。库没有推导引用覆盖、授权或服务静止；
即使成功也报告production_ready=false，不可用于现行生产维护。

## 引用报告绑定与历史读取增量

`prepare_reviewed`接受原计划及V2引用报告文件和显式预期报告摘要，校验报告→计划
摘要、四目录候选字节、保留集属于候选集、闭包已检查和计数。自动剔除全部pinned
记录；若全部须保留，返回NO_ELIGIBLE_RECORDS且不建立事务目录。原始计划与报告
以私有副本保存到归档事务内，摘要纳入持久清单；apply/rollback前复核该证据未变。
源主机候选inode不与恢复副本inode混同，恢复后的候选仍按原字节摘要约束。

`lookup`沿持久事务清单定位仍在原目录、已归档或已回滚的记录，验证原路径/摘要，
返回原始字节。查不到就拒绝，不拿latest替代，不把旧记录当作当前交易证据。

限定报告的all_references_proven=false继续保留。本函数不重新证明其他命名空间
在报告之后未改变，也不把闭包标志当作全引用或生产维护授权。生产目录保护不变。

新增六项回归在实现前失败、原十二项通过；接线后十八项通过。全部候选被保留的

合成引用报告做完整集成：备份→隔离恢复→报告绑定→保留引用/归档→原字节查回→
回滚，原JSON逐字节相同，待处理订单等状态与备份一致，源目录未改；该项通过。

## 真实读取模块的隔离归档兼容性

真实维护窗口已经完成备份与隔离演练，但生产入口仍不存在；本库仍拒绝保护中的
运行目录，不得通过改路径、猴子补丁或解除isolated检查将其当作生产归档工具。

新增tests/tools/test_demo_retention_readers.py，用原生保存/读取模块生成三类记录，
验证引用报告保留的BTCUSDC旧origin仍可由origin.load精确读取；origin、resident、
executor observation的load_latest在候选移动后均保持原值；归档记录可由lookup
按原路径和摘要返回原字节，回滚后完整目录文件逐字节一致。全部使用合成数据，
origin测试注入离线传输及测试凭证，不访问真实凭证或网络。

该测试不证明全量历史消费者已支持归档路径：运行时精确origin读取仍依赖原文件
路径，因此被引用记录必须保留。BTCUSDT使用同一origin读取模块，但本次新增
测试没有单独构造BTCUSDT原始记录，不能将该案例描述为两个市场实测。生产引用
闭包、人工/控制器并发约束和正式归档入口仍需单独完成。验证输出在
/home/kerstker/quantos-dev-output/maintenance-window-20260924/reader-compatibility.log
及readers-retention-final.log；不扩展4ffc管理员包或完整发布验收范围。

## 显式多批归档读取

lookup_many支持在调用方明确提供的最多32个离线归档事务中按原路径读取历史。
按固定路径顺序取得全部事务锁后校验每个清单及证据，清单总记录数最多100000；
重复归档参数、同一记录被多个事务声明、源/归档重复放置、损坏清单均拒绝。
未归档记录从源按摘要读取；没有记录则报告缺失，不替换为latest，不搜索未声明
目录。该接口不建立目录索引完整性，不允许读取受保护生产根，也不提供归档授权。

新增八项回归先因接口缺失失败，实现后与单批事务及真实读取模块联合28项通过，
Ruff E9/F821通过。输出位于maintenance-window-20260924/archive-lookup-before.log
和archive-lookup-after.log。此增量尚未进入固定4ffc演练包或已部署运行代码；
正式生产归档入口、受控停写和引用覆盖仍未解决，不得据此宣称容量恢复。
