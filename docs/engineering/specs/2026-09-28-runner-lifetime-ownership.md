# Runner 服务独占与重启核对

直接检查发现 Runner 已有启动时 reconcile_interrupted_runner_runs；此前路线记录中
“尚需处理 running 遗留记录”不能解释为没有该功能。实际缺口是它在启动时直接假设旧
执行器已退出，没有服务生命周期独占约束。回归证明第二个服务实例会把第一个的运行记录
改为 error，而不是拒绝重叠启动。

新增 Linux 服务生命周期 flock，在任何启动核对之前取得，持有至调度线程与队列完全退出。
第二个使用同一状态根的新版服务返回 RUNNER_ALREADY_OWNED，不触碰原运行记录。
锁文件保留，不删除重建；拒绝链接、非普通文件、额外硬链接和超出0600的权限。
不以心跳过期或 PID 数字推测执行器死亡。

退出时先通知定时循环停止，等待已经进入 to_thread 的调度完成，再等待全部队列 Future。
取消关闭协程不会提前释放锁；即使调度任务异常，也先等待队列退出。
JobQueue.join 先等待所有 Future 完成，再传播结果异常，避免首个异常留下其他执行线程。

## 验证

重叠服务与退出等待两个回归先失败。六组联合 **125 passed，1 skipped**；随后补强
调度异常也必须等待队列的 finally 路径，所有权/重启两组 **8 passed**。
包含真实子进程持锁时拒绝第二个拥有者、os._exit(77) 后原 inode 上重新取得锁、
取消关闭时仍保持独占、重启登记/审计和黄金轮次恢复回归。
Ruff（既有服务文件E9/F821）、治理和仓库卫生检查通过，未做canonical全量验收或部署。

## 边界

此独占协议约束使用新版服务生命周期的协作进程，不证明未升级旧服务、直接调用
JobQueue 的独立进程或外部写入者已经退出。首次迁移必须在已有发布流程中确认旧服务
终止，不能用新锁的取得冒充旧版本的存活证明。测试没有修改生产服务或真实运行记录。
异步进程强杀/断电耐久性、跨主机所有权及全局研究预算仍是不同问题。
