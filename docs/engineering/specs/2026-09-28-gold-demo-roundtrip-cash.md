# 黄金同轮开平仓与现金链联调

## 端到端证据

扩展 `tests/live/test_gold_demo_receipt_binding.py` 的合法路径，沿用同一 issuer policy/预算、dispatch/recovery/OMS、私有流及原账本：

1. 原黄金开仓完成成交投影和中断恢复后，读取确切持仓及成本。
2. 使用新账户观察生成 IOC 只减仓任务，重新提案并经过原独立签发器、风险检查和执行器。
3. 模拟第二笔订单发送；重复执行拒绝，HTTP 仅一次。导入第二笔私有成交和原编号查询，再投影 OMS。
4. 原持仓上下文重建两批结果：零仓位、零剩余成本，初始权益仍为 5000，累计手续费 0.02 后余额 4999.98。
5. 从同一私有流为两批重建覆盖现金窗口的日志，原现金链核对两次费用流水，余额残差为零。费用错绑成交编号必须拒绝。

以上传输、账户、签名密钥及 custody 均为隔离测试材料。不是实际 Demo、真实盈利或部署验收。

## 真实发现与修复

现金链首次返回 `CONTINUATION_BASIS_SOURCE_MISMATCH`。原因是执行持仓上下文对账本状态使用紧凑执行摘要，而原研究账本、现金链和账户恢复报告使用 `ai_factory_store.digest`，同一账本状态的摘要字节不一致。仅独立构造现金链材料的测试没有覆盖这一跨模块错误。

持仓结果、后续成本来源核对、跨日检查及账户现金消费者现统一使用原研究账本摘要。提案、授权、dispatch 和记录本身的执行摘要保持不变；没有新增账本或重新估计成本。跨日回归明确拒绝旧执行编码的账本摘要。

兼容边界：旧摘要绑定的提案、继续交易材料和跨日记录不能被静默重写或用双摘要放行。此变更尚未部署；旧持久记录迁移/重新授权需要单独审查，当前不证明已有部署状态可以无缝升级。
