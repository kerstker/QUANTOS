## 问题与修复

原编码器对已经生成的 tagged tree 重新序列化；原容器解码器为规范性比较
再生成两份 JSON。合法的宽 Unicode 容器虽然 UTF-8 wire 小于16MB，
仍可在原128MiB内存预算内因为这些临时副本产生 MemoryError。
编码、解码两个回归先真实失败，日志保留，没有调整原内存或 wire 限制。

编码器用原 expanded-byte/结构守卫检查实际生成的 tree，继续执行完整严格
round-trip。解码器完成原守卫和严格 tag reader 后比较规范 tagged tree，
保留字段类型、标量拼写、容器顺序和别名检查，避免序列化副本。
守卫只允许 exact builtin list/str/bool 的传输节点，因此此处 tagged tree
相等对应原 compact JSON 字节相等；比较已解码的值会丢失顺序与别名信息，
实现没有采用那种比较。原 V2 身份算法和哈希计算函数没有修改。

改动保留16MB wire、100000 native nodes、64层 native depth、
原传输结构/Unicode/数值边界；新回归还覆盖完整容器恰好16MB与超一字节、
嵌套错误顺序、重复/别名集合、非规范数值和非法 Unicode。
