# 高频公开行情的无损分段存储

2026-09-13，承接[备份状态与容量实测](2026-09-13-demo-backup-display.md)。
当前公开行情约每20秒追加一个 JSON；只读盘点估算约11天会触及研究快照100,000文件
上限。本增量把后续公开观察按UTC日写入独立 SQLite 段，逐条无损压缩，不删除原JSON。
本批尚未部署，不改变当前实际采集方式，也没有改变快照100,000文件/20GiB上限。

## 持续追加、读取与中断

`services/research/demo_observation_store.py` 是唯一新增的观察数据库持有者。
每条保留原报告的完整 JSON 字节、SHA-256、原观察时间和连续序号；成功、失败都保存。
压缩仅改变存储表示，读回时限制解压大小、核对原始长度、摘要和原报告模型。
段按观察时间的UTC日编号，不用新的写入时间冒充原始观察时间。

先以完整同步的事务提交报告，再原子发布 `DEMO_OBSERVATION_POINTER_V1` 指针。
提交后、发布前中断时记录仍在；同一报告再次投递不产生重复行，并可恢复指针。
目录锁覆盖日切换和指针发布；较早请求的延迟重试保留历史，不覆盖较新的观察。
正常 SQL 更新或删除已有观察及段元数据会被拒绝，读取不会创建缺失数据库。
这些限制不构成独立来源认证，也不能防止持有文件写权限的受信代码改造整个数据库。

每段最多10,000条、512MiB；每个观察目录最多3,660段，并保留8MiB写入空间余量。
这些是明确的存储预算，触及时失败并保留上一指针，不能解释为无限容量。
每个币种通常每天只增加一个段文件和原有固定指针/锁，消除该生产者按观察次数增加
小文件的方式。其他生产者、总字节增长、加密副本留存和中间材料回收仍需继续处理。

## 接线和恢复口径

公开采集 CLI 增加显式 `--archive-observations`。受保护执行采集与子进程采集模式
不能使用该开关；其原发布契约保持。市场模型支持读取原 JSON 和新指针，旧观察可继续
读取；未选择新方式时继续原存储。原行情视图、Console 响应、时间检查与前端图表不变。
采集源码摘要纳入两个存储模块，不能把新存储行为隐去或继承旧源码身份。

```bash
python -m tools.binance_demo_market_inputs --symbol BTCUSDC \
  --output-dir <隔离研究目录>/binance_demo_market_inputs/BTCUSDC \
  --archive-observations
```

写入面向DGX的POSIX身份与锁语义；旧JSON读取不因新增锁依赖而要求POSIX UID支持。
实际常驻采集只有在包含本增量的源码完成自身验收、核对运行目录和备份版本后才能接入。
不要在仍由旧备份/读取版本使用的目录上直接启用新格式。

研究冻结文件集合快照识别两币种的日段和固定空锁。每个日段使用原 SQLite 在线备份，
允许之后的追加继续；冻结指针必须指向已包含、摘要与币种都正确的记录。执行、签发和
控制器快照规则不因此放宽。恢复时逐条解压、核对报告与序号，并计算完整段内容摘要。
外层周期仅保存总记录数、两币种计数和段清单摘要，避免多年段数量撑破周期元数据预算。

快照仍是各文件的技术快照，不能称为跨进程共同时间点。新的摘要不重置记录时间、
交易风险或现金状态，不升级经济准入。原历史JSON、失败和加密备份均保留。
