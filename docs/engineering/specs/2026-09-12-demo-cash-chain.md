## 已实现的衔接

过去每份回执日志单独回放，现金比较只接单一空仓起点；多批次部分减仓和五分钟现金
窗口不能借此宣称连续核对。本批增加 `project_cash_chain`，以原始空仓起点只创建
一个 Decimal V2 账本，跨批次保留精确持仓成本、费用、资金费、外部资金、现金流水
身份和同日容量使用量。原单批转换/应用函数提取共用，不复制现金或成本计算算法。

后续日志的账户起点作为**观察检查点**，不把观察钱包重新当成初始本金。检查其
同币种持仓范围、数量、精确成本和钱包是否等于原账本前缀；成本来源摘要必须绑定
实际计算的前缀状态。观察时段可能包含成交或资金变化时，保持未知，不用舍入均价
估填成本。后续只减仓回执仍要求方向相反、数量不超过此前真实回放持仓。

同一账户/合约/规则、同日容量合同和唯一订单/交易身份均须一致；回执窗口可以重叠，
必须连续覆盖现金查询范围。缺口、重复批次编号、规则变化、费用缺失、未终态、
不一致的佣金/已实现收益或无法确定时钟归属不产生匹配。每批仍遵守原 150 秒回执
上限，整条链最多 32 批和 10,000 条已读取回执；没有放宽原窗口来凑五分钟。

V3 各批保留原双时钟区间，不能混用新旧时钟；现金跨重叠区间时取可用包络，不选择
最有利的偏差。原 500 ms 内部漂移仍是假设，精确延迟未知。页面可用时间包括整个
声明覆盖范围和最后取得的时钟材料，回顾输入不被视为当时决策已知。

`tools.demo_cash_chain` 只读已有 SQLite 日志和固定现金文件，保存不可变完整报告，
可发布经过严格结构检查的显示副本。文件字节摘要与语义报告摘要分开，重复回放不
新增相同报告；输出不能覆盖输入。Console 只读取显示副本，TypeScript、API 合同
与原模拟盘“唯一账本现金核对”区同步，展示原始净值、累计钱包、剩余数量/精确
成本、累计费用、失败和衔接来源。过时的固定窗口不声称当前账户持仓。

```bash
python -m tools.demo_cash_chain \
  --journal <original-first-journal.sqlite3> \
  --journal <next-batch-journal.sqlite3> \
  --cash-window <fixed-cash-capture.json> \
  --output-dir <isolated-report-directory> \
  --publish-dir <research-state>/data/cache/binance_demo_cash_chain
```

该命令不采集新输入、不签发、不提交、不修改原 OMS/恢复/日志，也不产生账户现金
来源认证。未知结果返回 2，输入/输出失败返回 3，保留诊断；成功仍是技术属性。
