## 实际增加的流程

已准备的受保护请求 → root 总控领取唯一请求摘要 → 执行身份检查原始输入并保留提案
→ 独立断网签发身份核对部署政策、账户、风险、批次与额度 → 签发日志先预留再签名
→ 原执行进程验签、重新检查原状态并持久化意图 → 原单次网络入口 → 保留结果或原编号恢复。
签发、订单状态、实际成交与唯一现金账本是分别核对的事实。

`live/execution/demo_issuer_policy.py` 复算已有风险检查，核对原始账户、行情、持仓、
日内损益与权益峰值约束。政策固定账户、部署、公钥注册表、执行版本、策略、已有
mandate/validation/风险参数摘要，以及币种、方向、IOC/GTX、是否允许开仓和逐单/批次额度。
签发有效期取政策、公钥、已有 mandate、原始行情新鲜度及本次 TTL 的交集。
它验证部署提供的材料，不能把请求中的姓名或 `approved` 标签变成人工批准。

`live/execution/demo_issuer_store.py` 保存签发预算与原始批准记录，独立于现金账本。
SQLite 事务先占用次数、订单数、名义金额及原编号，之后才允许签名；进程崩溃时预留
保留，不退款、不重签、不重发。原记录包含当时政策与公钥注册表，可核对签名和追加链。
同一政策 ID 不能改换内容。单库上限 20,000 条/128 MiB，不能通过重建库重置预算。
完整本地链核对不是独立外部锚，也不授予经济权威。

撤单使用独立次数与订单预算，只允许本签发日志中已经签名的原批次和原编号，不增加
开仓金额。原执行侧仍负责读取私有查询记录、核对新鲜度与场所编号，并在单次 DELETE
之前再次检查；签发进程不读取执行侧数据库。

`tools.demo_issuer` 只接受 root 拥有的 0600 FIFO 管道。签发密钥文件在读取第一个
字节前检查 root 所有权、独立签发组及读权限；不接受额外执行组身份。
如果签名后配置变化或管道中断，保留签名和占用额度，报告交付未确认；不能误报为
可重试的“未签发”。错误响应不回显私有异常、原始提案或密钥。

`tools.demo_supervisor` 只读取固定目录内、文件名与内容摘要相符的 root 私有请求。
领取请求采用排他创建和落盘，之后仅启动两个属于本次任务的临时 systemd 进程。
签发身份断网并无法访问执行凭证/状态；执行身份无法访问签发密钥/状态。
交接只有一次，不自动生成批准、新订单号、风险输入或重试请求。
本次子进程结束后只清理自身临时单元，不重启既有采集或研究服务。

## 固定部署合同

| 文件或目录 | 用途与归属 |
|---|---|
| `/etc/quantos/demo-issuer/authority.json` | root 提供的公钥注册表镜像，必须与执行侧逐字段一致 |
| `/etc/quantos/demo-issuer/policy.json` | root 提供的 `DEMO_ISSUER_POLICY_V1`，全部限额及材料摘要显式填写 |
| `/etc/quantos/demo-issuer/signing-key.json` | root:签发组、0640；`DEMO_ISSUER_KEY_V1`，含 authority_id、key_id、32 字节 Ed25519 私钥的 base64url 编码 |
| `/var/lib/quantos-demo-issuer/issuance.sqlite3` | 预先安装的签发身份私有追加库；运行时不初始化 |
| `/var/lib/quantos-demo-issuer/results`、`views` | 预先安装的私有尝试记录与展示输出目录 |
| `/var/lib/quantos-demo-controller/requests`、`claims`、`results` | root 0700，分别保存完整原请求、领取记录和原返回值 |

政策窗口最多 7 天，单次 TTL 最多 60 秒；这是资源边界，不是默认交易参数。
开单及撤单政策各最多 4,096 次/50,000 单，实际较小额度由部署政策显式确定。
观察、尝试和总控历史分别有文件数与字节上限，到限停止写入；归档与新目录备份仍须
纳入后续长期运行工作，不能称为无限持续运行已验收。

本增量没有生成或安装实际私钥、公钥登记、人工身份、mandate、validation 或订单请求。
上述路径是接口合同，不表示 DGX 已有这些材料。运行使用已验收的不可变发布路径；
源码位置、提交和完整验收证据均需通过原核验入口。

## 前后端

`tools.demo_issuer_observe` 从已有签发库的同一只读事务取得完整链，导出政策、有效期、
每种用途的预留/已签名/订单数及剩余名义预算。原始提案、签名载荷、私钥与经纪凭证
不进入展示。观察进程不读私钥，因此界面不声称密钥已经可用。

已有只读发布工具增加 `--kind issuer`，研究端读取
`data/cache/binance_demo_issuer_status`。Console、TypeScript 严格解析和 API 合同同步新增
`issuer_status`。展示 120 秒过期，保留缺失、损坏、未来及历史记录；政策过期按当前界面
时钟另作提示。服务端用精确有理数检查金额恒等式，浏览器用 BigInt，不把小差额舍入掉。
Studio 增加“独立签发与额度”，分别展示预留与签名，提供可横向滚动的额度表和来源详情。
