# 维护窗口内的新鲜证据准备

`demo_maintenance_window.prepare_evidence` 现在在已暂停窗口的同一排他锁内核验服务状态，调用准备协调器，并在成功返回前复查暂停。协调器验证固定发行版和公共身份注册表、检查相关进程，在本窗口唯一的私有工作目录中顺序执行 PLAN、管理员引用审查、CAPTURE。

两个执行UID子进程复用有界systemd交接：关闭网络、隐藏凭证目录、只读挂载执行状态，唯一可写位置是本次准备目录。原归档写入入口不用于准备。CLI仅输出有严格字段、数量和摘要约束的结果；错误原文不输出。准备动作不会签发归档授权。

启动前持久化单元及任务摘要；只有退出状态、结果协议和实际cgroup排空均通过才记录完成。重复调用拒绝覆盖原工作。引用审查或捕获失败保留前缀；恢复服务前总是重新核对全部准备子进程已退出，活子进程阻止移除启动抑制。失败但已排空的只读准备不阻止恢复原服务状态，也不成为归档证据。窗口恢复后的准备不能作为新窗口证据。

验证：准备worker/协调器、窗口、交接、捕获及证据导出联合 **56 passed**，Ruff通过。包括窗口真实文件锁冲突、意图先写后启动、重复任务拒绝、引用失败、未知进程扫描和恢复前子进程阻断。root身份、注册表及systemd在协调器测试中用替身；实际合成账户文件的备份与归档/回滚仍由贯通测试覆盖。没有启动新的root沙箱、改变现场服务、读取凭证或归档生产资料。
