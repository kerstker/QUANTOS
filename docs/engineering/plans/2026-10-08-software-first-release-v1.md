# QUANTOS 首次软件发行 V1 收口

状态：用户于 2026-10-08 明确调整优先级，先完成软件并交付第一个可发行版本。
完整系统闭环目标继续保留；真实研究、策略及现场运行的验收在软件发行后进行。
本文件的执行顺序优先于旧交付清单中要求先取得真实样本才制作发行版的工序。

## 固定软件范围

复用现有架构，完成研究入口、登记与完整试验记录、V2成本后回测、冻结前向、
风险与核验接口、受控模拟执行、唯一现金账本、恢复、反馈续轮、控制台和安装。
保留已确认的产品范围；各产品实际数据与现场接入状态单独显示，不虚报通过。
不在本版增加策略优化、TabPFN、机构异机设施或新市场。

## 五项软件收工条件

| 编号 | 必须交付的结果 | 核验方法 |
|---|---|---|
| V1-1 核心流程 | 现有研究、账本、风险、核验、执行与反馈接口连贯；原候选身份和完整试验历史贯通 | 隔离、明确标注合成数据的端到端场景，覆盖正常、淘汰、拒绝和中断恢复；不能以文件存在替代行为 |
| V1-2 操作入口 | 用户能创建研究、查看成本与失败原因、读取审核状态、查看账本与反馈 | 同版 API/前端合同、类型与构建，以及实际浏览器操作；未知值和未配置状态如实显示 |
| V1-3 保护边界 | 未配置真实核验或授权时，研究/仿真可用，真实下单不可用；配置错误有可理解的阻断原因 | 原治理、风险与授权负例；不能把合成签名或模拟盈利作为实际权限 |
| V1-4 固定版本 | 最新软件冻结为唯一干净提交，完整软件门通过，制品与源码同版 | 原 scripts/validate.py 完整门、适用 ARM64 构建/扫描/离线冒烟、证据留存；不继承旧版或专项 PASS |
| V1-5 发行材料 | 可下载的软件包、依赖、匹配前端、安装/启动/停止/升级与恢复说明、已知限制和校验摘要 | 在隔离安装根验证包及入口；现场替换服务作为可审阅交付后的单独步骤 |

能够正确阻断未配置或不合格输入是软件行为。尚未实现的必要接口不能借此标成完成；
上述端到端场景必须核对实际源码能力，不能仅用始终返回不足的桩覆盖一个声称可用的功能。

## 不再阻塞首次软件发行的真实材料

真实数据采集时长、八个完整活动前向周、独立 OOS 封存与访问历史、真实核验签发、
Windows 审计诊断回执、场所账户与实际成交现金、现场整组恢复及实际24小时运行，
均进入发行后真实运行验收。它们保持未完成，既不伪造，也不折算为 PASS。
不得为了发行安装 trust、接触私钥/交易凭据、降低原风险阈值或制造人工授权。

盈利策略开发按用户要求在平台软件交付后单独推进。当前候选失败或不足不阻止
制作软件发行版，也不使该候选获得交易资格。

## 执行纪律与终点

先收尾正在修改的冻结验证软件交接并核对 V1-1 至 V1-3 的现有端到端入口，
只修缺失的软件行为与发行阻断。接口收口后冻结一个候选，集中执行 V1-4、V1-5。
完整门若失败，保留原失败，只处理具体阻断；通过后不继续增加外围检查或功能。

发布时分别报告：软件 V1 是否发行、真实运行哪些条件未配置、完整目标哪些现场
验收未完成。软件发行不要求先找到盈利策略；首次软件发行通过也不冒充实盘闭环完成。

原总范围和后续现场条件见 [整体缺口分析](2026-10-07-system-delivery-gap-audit.md)；
研究/实盘边界沿用 [研究优先决定](../specs/2026-09-20-dgx-research-first.md)。
