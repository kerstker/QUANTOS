跨环节身份：source → hypothesis → dataset/as_of → feature/model spec → trial →
frozen model → forecast → target → order/rejection → cashflow → attribution → new hypothesis。

任何仍未完成的软件工作继续标记待实现，不以外部条件为理由提前宣称软件全部完成。


## 本轮实现范围与明确限制

- R0：36 对象机器目录与可检索来源页；当前公开来源抓取绑定任务，失败回执保留。
- R1/R2：V2 的 72 个受限组合规格，原 V1 的 18 个规格及冻结模型保持兼容。
  QWEN 读取来源与内层摘要；按规格排除跨轮尝试，并在单轮内检查相同预测与相同决策阈值的指纹。
  72 个规格不是 72 个独立 Alpha，也不是任意代码生成。失败仍消耗预算。
- R3：固定周期 / 成熟预测落后零基线触发的有限研究计划，原数据库内事务预留，
  Runner invocation 幂等恢复、暂停/停止、冷却、最大 72 次主实验、最多八个观察模型。
  过程对照另计：AI 每轮 9 × 主预算，基线每轮 6 × 主预算；压力情景不算独立候选。
  跨轮只传内层得分与状态，不传外层结果。计划停止不强杀正在执行的轮次。
- 模型演进：自然误差与零预测基线、共同成熟标签比较、研究挑战者建议；不静默
  替换旧模型，不自动经济晋级。观察停止沿用已有冻结模型控制，记录不删除。
- R4：技术回放直接投影唯一账本现金流、对账残差与末尾成交；没有制造真实场所
  TCA 或解封新 Paper 持久化。实际来源/结果权威与场所故障回执仍必须外部形成。
- R5：原共享账户加入/替换回放增加预测相关性、分歧与容量情景标识；真正多策略
  合格组合仍缺少独立经济样本，不能按相关性表替代合格策略。
- R6：新增生命周期工作台，计划轨迹、模型演进、来源检索、预算与等待原因；
  实验页显示来源读取、AI Token/耗时、技术成交与现金流。检查点验证计划与轮次绑定。
