# QUANTOS v1.0.0 安装与首次使用

本版为 Linux ARM64 / Python 3.12 的研究与仿真软件，Windows PC 通过浏览器操作。
软件源码 `9589c47ac341e1d6c27fdc5d2fdeabb8973b91a8`，带发行证据的制品 `1b1b661ad49789827e81432a23ba60074d32c2a5`。
原完整软件门32阶段、两次同版冷构建、运行镜像零已知漏洞扫描、离线只读冒烟，
以及隔离根文件系统中的实际安装、移位安装和安装后浏览器六项检查均已通过。
现场原服务尚未替换；包中合成样例不代表市场数据、盈利或交易资格。

## 获取发行包

从 [GitHub Release](https://github.com/kerstker/QUANTOS/releases/tag/v1.0.0) 下载 `QUANTOS-Software-V1-Linux-ARM64-9589c47a.zip` 和同名 `.sha256` 文件。
保持 ZIP 与摘要文件在同一目录，先核对发行包，再解压核对内部每个文件：

```bash
sha256sum -c QUANTOS-Software-V1-Linux-ARM64-9589c47a.zip.sha256
unzip QUANTOS-Software-V1-Linux-ARM64-9589c47a.zip
cd QUANTOS-Software-V1-Linux-ARM64-9589c47a
```

本版要求 Linux ARM64 / Python 3.12、Git，以及允许执行程序和加载动态库的安装文件系统。
已构建网页随包提供，安装和运行此包不需要 npm。Windows x64 为浏览器操作端。

## 校验和安装

在 DGX 的普通用户终端解压软件包，进入包含 `install.py` 的目录，执行：

```bash
sha256sum -c SHA256SUMS
sudo /usr/bin/python3.12 -I -B ./install.py
```

安装器使用固定离线依赖，安装同版代码、venv和前端；不启动或切换现有服务。
`/opt/quantos/releases` 与 `/opt/quantos/venvs` 须为已有、root所有且无组/其他写权限的
安装父目录。新机器可执行下面的命令创建缺失目录；已有目录的权限保持不动，
安装器仍会验证其所有者、权限和路径：

```bash
sudo /usr/bin/python3.12 -I -B - <<'PY'
from pathlib import Path
for path in (Path('/opt/quantos'), Path('/opt/quantos/releases'), Path('/opt/quantos/venvs')):
    if not path.exists():
        path.mkdir(mode=0o755)
PY
```

创建目录后运行前面的安装命令。不要修改其他现存版本的权限。
安装文件系统须允许执行程序和加载动态库；`noexec` 挂载不适合安装 Python 运行环境。
软件包允许改换解压位置，`install.py` 只改绑定的文件位置，原版本和摘要检查保持。

## 启动和首次使用

在三个终端中，先在解压目录执行下面两行。需要自选状态目录时，在 source 前
设置 `QUANTOS_STATE_ROOT` 为自己的空的绝对目录；默认使用用户目录下的私有新目录。

```bash
QUANTOS_V1_PACKAGE="$PWD"
source "$QUANTOS_V1_PACKAGE/activate-software-v1.sh"
```

三个终端分别启动一个入口：

```bash
# 终端一：只读控制台 API
"$QUANTOS_V1_PYTHON" -P -B -m uvicorn services.console.main:app --host 127.0.0.1 --port 18400
```

```bash
# 终端二：受控研究引擎，首次会创建私有的本地研究访问令牌
"$QUANTOS_V1_PYTHON" -P -B -m uvicorn services.research_runner.main:app --host 127.0.0.1 --port 18420
```

```bash
# 终端三：同版网页及本地 API 转发
"$QUANTOS_V1_PYTHON" -P -B -m tools.local_frontend_server --host 127.0.0.1 --port 18413 --console-port 18400 --runner-port 18420
```

本机浏览器访问 `http://127.0.0.1:18413`。Windows 操作端通过已有的 DGX SSH 连接
转发18413端口后访问同一个地址；API不需要另行对外开放。例如，在 Windows PowerShell 中
用自己的 DGX SSH 用户和地址替换 `user@dgx-host`：

```powershell
ssh -N -L 18413:127.0.0.1:18413 user@dgx-host
```

保持这个 SSH 窗口打开，在 Windows 浏览器访问 `http://127.0.0.1:18413`。
页面要求的研究令牌在
所选状态目录 `key/research_runner_token.txt`，只在自己的操作页面使用。

无需真实数据即可查看研究记录、未配置状态和失败原因。要运行包中已验证的合成
技术回放，在新状态目录准备输入，保留任何已有输入文件：

```bash
mkdir -p "$QUANTOS_STATE_ROOT/data/cache/perpetual_replay"
cp -n "$QUANTOS_V1_PACKAGE/examples/synthetic-capture-v2.json" "$QUANTOS_STATE_ROOT/data/cache/perpetual_replay/capture-v2.json"
```

然后在研究页面选择永续技术回放入口并创建任务，查看原费用、结果和账本。
该样例只验证软件流程，结果为 `TECHNICAL_VALIDATION_ONLY`。缺输入时页面会保留
明确失败，核验未配置时保持不足，不妨碍软件启动或其他研究操作。

## 停止、升级和恢复

停止接收新研究并等待当前任务结束，然后在三个终端正常停止相应进程。重新启动
使用同一个状态目录，保留任务、试验、失败和中断历史。不要强杀正在写入的研究。

升级先安装新版本并保留旧版本，再停止原写入进程、备份整个状态目录，核对新版
对原数据格式与历史的校验结果后切换入口。安装本身不会替你完成现场服务切换。
恢复使用同版软件和停止写入时的完整状态备份，不拼接不同时间的SQLite文件，
不删除实验/审计历史。历史或原件校验失败时保留错误及原目录。

## 软件使用问题定位

| 现象 | 检查项 |
|---|---|
| 不能创建安装目录 | 用管理员执行安装；核对父目录的 root 所有者和现有权限 |
| 动态库提示 failed to map segment | 检查安装文件系统是否设为 noexec |
| 页面连接失败 | 核对三个本地服务是否在运行，以及 Windows SSH 转发是否保持连接 |
| 研究请求返回 401 | 使用当前状态目录自己的本地研究令牌 |
| 回放缺少输入 | 在当前状态目录放入随包的合成 capture，再创建新的研究任务 |
| 核验状态显示未配置或不足 | 软件可以继续研究操作；真实核验材料在后续阶段配置 |

保留原错误、失败任务和已有历史。安装通过与现场服务切换分别处理，运行中的旧服务不会自动被替换。
