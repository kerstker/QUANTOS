当前机器没有 Go 编译器，且 Binance 公共 REST 在本环境连接超时。因此没有冒充“原生 Go 已执行”。本次采用逐行 Python 端口复核包内 `lance_backtest.go`，使用项目本地同一 Binance 1m 缓存：

- 精确窗口 `[2025-12-17, 2026-06-30)`：280,800 根；
- 全窗口 `[2025-07-01, 2026-07-09)`：537,120 根；
- EMA：首根收盘价初始化；
- 预热：从第 50 根开始交易；
- 目标：前一根偏离大于 0.5%，当前偏离小于 0.3%；
- 止损：前一根 K 线高低点外 0.2%；
- 费用：逐笔按包内 cash 逻辑扣除；
- 滑点、资金费、盘口冲击、延迟：未加入。

端口保留了源代码的统计特征：现金账本同时扣开仓和出仓费用，但 `Trade.NetPnL`、胜率和 Profit Factor 只把出仓费用计入交易统计。

## 5. 与原专业版策略的关系

包内 Go 回测并不是原始专业版 Markdown 的同一规则：

- 原专业版目标止盈是当前偏离小于 0.15%；
- 包内 Go 代码要求前一根偏离大于 0.5%，当前偏离小于 0.3%；
- 原文连胜加码未实现；
- 包内 Go 回测使用固定 40% 仓位；
- 包内 Go 结果没有纳入资金费、真实成交延迟或 Tick 逐笔成交。

所以本次结果证明的是：**包内 Go 算法版本在 1bp 理想成本模型下具有历史正收益**，不是对原始专业版 Markdown 的严格复现。

## 6. 纸盘证据判定

包内报告称 DGX 纸盘 6 天、11 笔交易、8 条轨道全盈利，但技术包没有提供原始账本、逐笔订单、原始事件或独立哈希证据，无法纳入 QUANTOS 的前向证据链。6 天 11 笔也远低于稳定性判断所需样本。

QUANTOS 当前纸面门仍要求真实前向周期积累；当前三 Alpha 的有效前向周期为 `0 / 8`。因此技术包结果不能直接解锁纸面或实盘。
