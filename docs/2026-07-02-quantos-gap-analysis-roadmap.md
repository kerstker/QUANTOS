## 文档目的与范围

本文档基于对以下两份设计文档的评审:

- `2026-07-02-capital-allocator-design.md`(Rank #4:多 book 资金分配)
- `2026-07-02-crowding-gate-design.md`(Rank #3:拥挤度门禁)

评审范围说明:目前只看到这两份设计文档,没有看到 Rank #1、Rank #2 的实现细节、`docs/PROJECT_STATE.md`、`docs/QUANTOS_TOPTIER_REMEDIATION_ROADMAP.md` 全文,以及更早期的数据管道/研究框架。下文有几处标注为"待确认"——如果相关能力已经在别处落地,对应条目可以直接降级或去掉。建议的后续 Rank 编号只是为了讨论方便,具体排期请以你现有的路线图文档为准。

## 一、结论摘要

| 文档 | 结论 | 核心优点 | 实现前建议明确的问题 |
|---|---|---|---|
| capital_allocator(Rank #4) | 有条件批准,可以进入实现 | 纯函数、fail-closed 覆盖全、conservative fractional Kelly 的选择正确 | 协方差缺失、样本统计量无收缩、quality_multiplier 来源未定义 |

## 二、capital_allocator(Rank #4)详细评审

### 优点

- `raw_score = max(mean - min_positive_mean, 0) / variance` 是标准的单资产 Kelly 近似(edge / variance),配合 `kelly_fraction = 0.25` 是业内公认的保守做法:满 Kelly 对参数误差极度敏感,即使参数完全准确,也有不小概率出现 50% 以上的回撤,四分之一 Kelly 是常见的工业级折衷。这个选择本身没有问题。
- fail-closed 规则覆盖得很完整,容量、质量乘数、历史权重全部"无效即 BLOCK",方向是对的。
- 把资金分配和执行路径彻底解耦(不读 `DryRunStore`、不进 `services.execution`/`services.risk`)是正确的边界划分。

### 需要解决的问题

- **[P0] 组合层面缺协方差。** 目前的方法是每个 book 独立算 Kelly 分数,再把所有正分数归一化求和到 1。这不是真正的组合 Kelly——完整的多资产 Kelly 最优解形如 `f* = Σ⁻¹μ`(协方差矩阵的逆乘以均值向量),而不是把每个 book 当独立资产打分后再相加。如果两个 book 收益相关性高,当前方法会系统性地对这一对 book 超配,因为它隐含假设了 book 之间互相独立。Rank #1 里"`crowd_contra` 单独跑赢组合"的结论,是对某一批具体回测数据的观察,不能当作"可以放弃协方差建模"的方法论依据——book 数量增多之后这个问题只会更突出。诊断部分已经计划算 `risk_contribution_pct`,说明协方差数据本来就具备,建议下一步直接把这个闭环打通:不只是事后报告风险贡献,而是让协方差参与约束或打分本身。
- **[P0] Kelly 输入的估计误差没有收缩机制。** `min_observations: 20` 配合直接使用样本均值和总体方差算分数,在 n=20 时均值的标准误差非常大,而 Kelly 公式对输入误差的放大效应是金融文献里反复强调的问题:参数的轻微偏差就可能让分配结果大幅偏离最优。建议在 raw_score 里加入基于标准误差的收缩项(比如把分数往 0 收缩,收缩强度是观测数量的函数),而不是用一个和观测数量无关的硬阈值。这可以作为同一版实现里的小增量,不必单开新 Rank。
- **[P1] `quality_multiplier_by_book` 的来源未定义。** 设计文档规定了它必须落在 `[0,1]` 且有限,但没有说这个数字应该怎么算出来。如果最终由人工填入,这个原语标榜的"确定性"和"可解释性"会打折扣,变成一个隐藏的主观旋钮。建议后续做一个独立的信号质量评分原语(见下文 Rank #6 建议),用样本外/dry-run 证据系统化地产出这个乘数,而不是人工输入。
- **[P1] 容量重分配的收敛细节没写清楚。** "excess redistributed to uncapped room" 需要明确:第一轮重分配之后,如果某个原本没有上限约束的 book 又被推过了自己的上限(容量约束级联触发),要不要继续迭代?这是经典的 waterfilling(注水法)问题。建议在设计里显式写出迭代终止条件,并加一个"三个 book、需要两轮才能收敛"这类测试用例。
- **[P2] 数值容差和数值稳定性未指定。** "sum to 1 within numerical tolerance" 里的容差具体是多少(1e-6?1e-9?)没有写清楚;方差计算建议显式要求数值稳定的算法(两遍法或 Welford 在线算法),避免朴素公式在特定输入下出现精度问题。作为一个要被当作治理级别原语的模块,这类细节值得写进规范,而不是留给实现自由发挥。
- **[P2] 容量是硬上限,不是衰减曲线。** 真实策略容量通常随资金量增加边际收益递减(市场冲击成本),而不是非黑即白的美元上限。目前的硬上限适合作为第一版简化,建议在文档里显式标注这是简化,并作为未来 Rank 的候选项,而不是隐含地当作长期方案。

## 三、crowding_gate(Rank #3)详细评审

### 优点

- 对"未知证据"一律 fail-closed 到 BLOCK,这是历史上多次拥挤交易平仓螺旋(比如 2007 年 8 月那次多只市场中性量化基金几乎同时巨亏的事件)里最容易被忽视、但也最重要的一条原则:不知道不等于安全。
- `min_coverage` 门槛能防止"只测了一小部分仓位就当整体安全"的漏洞。
- 空头按绝对值计入分数和覆盖率,方向正确——拥挤度是集中度风险,不是方向性判断。

### 需要解决的问题

- **[P0] 加权平均分数会被稀释。** 目前的 `score` 是覆盖标的的 gross-weighted 平均拥挤度。如果 90% 仓位在低拥挤标的、10% 在极端拥挤标的,加权平均很可能仍然落在 PASS 区间,但这 10% 的尾部风险可能才是真正致命的(这正是 2007 年那次危机的模式之一:少数极端拥挤的头寸被平仓引发连锁反应)。建议加一个并行判据:最大单一标的拥挤度,或者按拥挤度排序后头部集中度指标,任一超阈值都单独触发 WARN/BLOCK,而不是只依赖整体加权平均。这个改动不大,建议直接并入 Rank #3 当前这版实现,不必单开新 Rank。
- **[P0] 完全没有流动性/成交量维度。** 拥挤度真正演变成危机,通常发生在"大家同时想退出、但没有足够对手盘"的时候。目前设计只用一个抽象的 `crowding_by_symbol` 分数,不涉及成交量或"按当前流动性估计的退出天数"。这是拥挤度冲击历史上最核心的传导机制,建议列为后续 Rank 的重点方向(见下文 Rank #8 建议)。
- **[P1] 没有时间趋势/加速度信号。** 现在是单次静态快照,没有"拥挤度是否在快速上升"的判断。经验上,拥挤度快速上升往往比绝对水平更能预示短期平仓风险。
- **[P1] 没有跨 book / 全公司层面的拥挤度汇总。** 当前接口只处理单一候选组合。QUANTOS 已经有多 book 资金分配(Rank #4),如果 book A、book B 各自看起来都不拥挤,但两者持仓高度重叠,公司整体拥挤度可能远高于任何单一 book——这恰恰是很多真实危机里最后才被发现的模式。建议把这个 gate 的输出后续接入 Rank #4 资金分配作为额外约束,或者单独做一个全组合拥挤度汇总原语(见下文 Rank #9)。
- **[P1] 阈值未经实证校准。** `threshold=0.60`、`warn_threshold=0.45` 目前看起来像是人工设定的整数。建议后续用有据可查的历史拥挤度驱动型回撤场景做一次实证校准研究,再决定是否维持这两个数字。
- **[P2] 证据新鲜度不在这个纯函数的职责范围内,但需要配套规范。** 设计里明确排除 wall-clock,这对纯函数是对的,但意味着"`crowding_by_symbol` 是多久之前算出来的、多旧就不该再信"必须由调用方负责。建议在集成层规范里显式写清楚这条职责边界,避免出现"用了过期数据但门禁显示 PASS"的情况。

## 四、与顶级机构标准对标:六大支柱现状

下面用量化机构常见的六个能力支柱,给整个 QUANTOS 路线图定位(不只是这两份文档)。

| 支柱 | QUANTOS 当前覆盖 | 差距 |
|---|---|---|
| I. 研究与信号验证(含模型风险管理) | 未在已提供文档中出现 | 没看到样本外验证、多重检验校正(deflated Sharpe ratio / probability of backtest overfitting)、时间序列交叉验证的 purge & embargo。这是"AI 量化"场景下最容易被低估、后果却最严重的一类风险——如果系统里有任何机器学习驱动的信号生成环节,缺这一层几乎必然会产生过拟合的虚假信号 |
| II. 组合构建与资金分配 | Rank #4(本次评审) | 协方差缺失、估计误差无收缩、质量乘数来源不系统 |
| III. 风险管理(因子/拥挤度/流动性/压力测试) | Rank #2(只读因子诊断)+ Rank #3(拥挤度门禁,本次评审) | 拥挤度维度单一、无流动性接入、无压力测试/情景分析原语 |
| IV. 执行与交易成本 | Rank #1(已交付,含成本、整数手、波动率目标) | 六个支柱里相对最成熟的一块;待确认是否有正式的 TCA(交易成本分析)回溯比较 |
| V. 治理、合规与运营风险 | governance boundary test(分散在 Rank #1-4) | 代码边界治理做得好,但没看到决策审计留痕(谁在什么时候批准了什么权重变化)、配置版本化、策略生命周期/熔断准则 |
| VI. 基础设施与数据完整性 | 未在已提供文档中出现(待确认) | 待确认:历史收益数据是否有 point-in-time 正确性保证、survivorship bias 处理、企业行动(分红/拆股)调整——这些如果有缺口,会让上面所有分析都建立在错误的地基上 |

## 五、建议的后续方向(按优先级)

延续现有"先做纯离线原语、再决定是否接线"的模式。下面的 Rank 编号只是为了讨论,请对照你现有的路线图文档重新编排。

### P0 —— 建议下一批就排期

- **协方差感知的资金分配升级(候选 Rank #5)**:把 Rank #4 从"独立 book 打分再归一化"升级为使用协方差矩阵的组合 Kelly,可以先用收缩协方差(比如 Ledoit-Wolf 收缩)避免小样本下协方差矩阵病态。仍然是纯函数,输入从 `returns_by_book` 扩展为可选的协方差矩阵(或从收益序列内部计算),不改变现有 API 的其他部分,向后兼容。
- **信号质量/过拟合控制评分原语(候选 Rank #6)**:系统化产出 Rank #4 需要的 `quality_multiplier_by_book`,基于样本外表现、deflated Sharpe ratio、或 probability of backtest overfitting 一类的统计量,而不是人工输入。这是"AI 量化系统"场景下最容易被忽视的一环——没有这一层,策略数量越多,虚假发现的概率越高,而且没有任何机制能把这个风险量化出来。同样是纯离线统计原语,不碰执行路径。
- **拥挤度门禁的稀释修复**:不建议单开新 Rank,建议直接并入 Rank #3 当前这版实现——加最大单一标的拥挤度或头部集中度并行判据。
- **决策审计与配置版本化原语(候选 Rank #7)**:给每一次资金分配变化、每一次门禁判定留下不可篡改的记录(谁/什么时候/用的哪个配置版本/输入是什么/输出是什么),阈值、`kelly_fraction` 等配置常数本身也要版本化。这是"独立风险监督"这道防线能够运作的前提——没有留痕,事后就无法复盘任何一次分配决策是否合理。

### P1 —— 接下来一到两个迭代

- **流动性/成交量感知的拥挤度扩展(候选 Rank #8)**:把拥挤度证据来源扩展到包含 ADV(日均成交量)或者按当前流动性估计的退出天数,而不只是一个抽象分数;同时加入拥挤度的时间趋势/加速度信号。
- **跨 book / 全组合拥挤度汇总(候选 Rank #9)**:在 Rank #4 分配结果基础上,汇总检查各 book 持仓重叠导致的公司整体拥挤度,作为资金分配的额外软约束或诊断项。
- **阈值实证校准研究**:不一定是代码原语,而是一次研究工作——用历史场景数据校准 crowding_gate 的 `threshold`/`warn_threshold`,以及资金分配里的 `no_trade_band`、`max_weight` 等常数,形成有据可查的校准记录文档。

### P2 —— 更长期

- **压力测试/情景分析原语(候选 Rank #10)**:对给定的候选资金分配,离线跑历史情景(有代表性的历史危机窗口)和假设情景,输出情景下的组合表现,同样是纯函数、不碰执行路径。
- **策略生命周期与熔断准则(候选 Rank #11)**:定义系统化的"何时该降低/暂停对某个 book 的分配"规则(比如连续 N 期夏普比率低于阈值、或回撤超过阈值),先做成纯离线评估原语。
- **容量衰减曲线(候选 Rank #12)**:把硬容量上限升级为容量-收益衰减曲线建模。
- **合规与监管准备(远期占位,不紧急)**:如果系统未来任何阶段要连接真实资金/真实市场,需要单独评审(不在本次范围内)——不同司法辖区的算法交易合规要求(比如 MiFID II 对算法交易系统的测试与熔断要求)、限制名单检查、最优执行义务等。现阶段 `L2_DRY_RUN_ONLY` 的边界设得很清楚,这块工作可以往后放,但建议现在就在路线图里留一个占位条目,避免临近上线时才发现这是一整块缺失的工作。

## 六、如果只能先做几件事

1. crowding_gate 的稀释问题(改动小)直接在当前这版实现里修掉。
2. 在资金分配器文档里显式写明"这是独立打分,非组合协方差 Kelly"这个已知限制,同时把协方差升级正式排进路线图,而不是无限期搁置。
3. 优先立项信号质量评分原语,这是"AI 驱动信号 → 资金分配"这条链路上最大的地基风险。
4. 立一个轻量的决策审计/配置版本化原语,成本不高,但是后续所有治理工作的前提。
